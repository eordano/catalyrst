# Product capabilities and assumptions

Code review: 2026-09-17. Generated by `npm run products:audit -- --write`.

This is a source-wiring audit, not a live deployment certification or a complete inventory of every route. Each product answers the same five questions. Similar rigor does not mean equal feature counts or identical prerequisites.

**Statuses:** implemented = a production path exists; partial = prerequisites or sub-actions remain incomplete; preview = simulated/local demonstration; unavailable = refuses the action. An implemented path still depends on authorization and working services.

## Administration

### Capabilities

- **Operator service inspection: implemented.** Evidence: [server.tsx](../packages/routes/app/routes/server.tsx), [server.render.test.tsx](../packages/routes/app/routes/server.render.test.tsx).
- **Moderation: partial.** Evidence: [places-moderation.ts](../packages/data/src/lib/catalyst/admin/places-moderation.ts), [whatson-admin.ts](../packages/data/src/lib/catalyst/admin/whatson-admin.ts).

### Assumptions to validate

- **Identity:** A wallet address alone does not grant an operator or moderator role; the write endpoint must authorize it.
- **Availability:** Service health and moderation reads can fail independently; an unavailable service is not an empty queue.
- **Persistence:** Only acknowledged moderation writes change shared state; some moderation actors remain previews.
- **Completion:** Require the requested action to be acknowledged and reflected by a subsequent read; a dialog closing is insufficient.
- **Measurement:** Separate queue inspection, attempted moderation, rejected writes and acknowledged decisions; do not mix preview decisions into throughput.

## Explorer entry and client controls

### Capabilities

- **Entry destination selection: implemented.** Evidence: [client.open-screen.tsx](../packages/routes/app/routes/client.open-screen.tsx), [client.open-screen.test.ts](../packages/routes/app/routes/client.open-screen.test.ts).
- **Chat and HUD controls: partial.** Evidence: [bevy-overlay.chat.tsx](../packages/routes/app/routes/bevy-overlay.chat.tsx), [bevy-overlay.hud.tsx](../packages/routes/app/routes/bevy-overlay.hud.tsx).

### Assumptions to validate

- **Identity:** Browsing destinations does not imply a connected Explorer identity; runtime actions need the client session.
- **Availability:** A compatible renderer and working bridge are prerequisites for client actions; a loaded web page is not a running scene.
- **Persistence:** Navigation is local until a client acknowledges it; chat persistence must not be inferred from a send click.
- **Completion:** Track destination arrival or bridge acknowledgement separately from opening the client or clicking Join.
- **Measurement:** Compare entry variants on the same destination-ready cohort and count startup/connection failures as guardrails.

## Creator entry

### Capabilities

- **Creator Hub entry and routing: implemented.** Evidence: [create._index.tsx](../packages/routes/app/routes/create._index.tsx), [disk.ts](../packages/data/src/lib/fs/disk.ts).
- **Capability-routed entry experiment: partial.** Evidence: [story.md](../packages/features/src/stories/create/capability-routed/story.md), [create-entry.ts](../packages/core/src/lib/experiments/create-entry.ts).

### Assumptions to validate

- **Identity:** Visitors may explore before sign-in; opening the hub does not grant ownership or publishing permission.
- **Availability:** File System Access support must be detected in the browser; a supported API can still be denied by the user.
- **Persistence:** A selected folder remains local until saved or deployed; downloading a tool does not create a project.
- **Completion:** A rendered project preview, not a download or hub click, proves the preview capability worked.
- **Measurement:** Segment browser capability and actual preview completion; a single populated arm is instrumentation, not evidence of lift.

## Creator Hub

### Capabilities

- **Project editing and deployment workflows: partial.** Evidence: [creator-hub.delete-project.tsx](../packages/routes/app/routes/creator-hub.delete-project.tsx), [deploy-world.server.ts](../packages/data/src/lib/catalyst/creator-hub/deploy-world.server.ts).
- **World permissions and metadata: partial.** Evidence: [creator-hub.world-permissions.tsx](../packages/routes/app/routes/creator-hub.world-permissions.tsx), [creator-hub.world-settings.tsx](../packages/routes/app/routes/creator-hub.world-settings.tsx).

### Assumptions to validate

- **Identity:** A valid session and ownership/delegated permission are separate requirements for each project, collection or world.
- **Availability:** Local file access, builder storage, content deployment and world services have different failure modes.
- **Persistence:** Local edits, backend saves and published content are distinct; metadata preview state is not a saved world setting.
- **Completion:** Use the returned project/entity identifier and a read-back or deployment status; a finished wizard is insufficient.
- **Measurement:** Measure first preview, saved draft and published scene separately, with failed uploads and permission denials retained.

## Governance

### Capabilities

- **Proposal and project browsing: implemented.** Evidence: [governance.proposals.tsx](../packages/routes/app/routes/governance.proposals.tsx), [governance.projects_.$id.tsx](../packages/routes/app/routes/governance.projects_.$id.tsx).
- **Submission and voting workflows: partial.** Evidence: [submit-governance-proposal.ts](../packages/data/src/lib/catalyst/governance/submit-governance-proposal.ts), [machine.ts](../packages/features/src/stories/governance/vote/machine.ts).

### Assumptions to validate

- **Identity:** A connected wallet is not proof of voting power, authorship or committee authority.
- **Availability:** Proposal reads, signing, Snapshot/DAO submission and discussion services are separate dependencies.
- **Persistence:** Drafts and preview votes are not published proposals or accepted ballots; unavailable writers must refuse.
- **Completion:** Require an accepted proposal/vote identifier from the authoritative service; a signature or outbound link alone is insufficient.
- **Measurement:** Report draft completion, external handoff and accepted votes separately; do not infer binding DAO outcomes from preview events.

## Events, profiles and community landings

### Capabilities

- **RSVP and cancellation: implemented.** Evidence: [landings.rsvp-event.tsx](../packages/routes/app/routes/landings.rsvp-event.tsx), [rsvp.test.ts](../packages/data/src/lib/catalyst/landings/rsvp.test.ts).
- **Notification preferences and submissions: partial.** Evidence: [subscriptions.ts](../packages/data/src/lib/catalyst/landings/subscriptions.ts), [submit-hangout.ts](../packages/data/src/lib/catalyst/landings/submit-hangout.ts).

### Assumptions to validate

- **Identity:** Public event reads do not authenticate an attendee; every write must use the current, unexpired identity.
- **Availability:** Events and notification settings are separate services; lack of a readable setting must not become an overwrite.
- **Persistence:** Acknowledged RSVP/preference changes are shared; hangout/schedule previews and email verification have separate readiness.
- **Completion:** RSVP succeeds after the attendee endpoint acknowledges the write; saving preferences does not prove an email was delivered.
- **Measurement:** Distinguish real from simulated RSVP events and cancellations; measure returning attendance separately from RSVP intent.

## Marketplace

### Capabilities

- **Catalog, listings and availability checks: implemented.** Evidence: [marketplace.buy.tsx](../packages/routes/app/routes/marketplace.buy.tsx), [names.ts](../packages/data/src/lib/catalyst/marketplace/names.ts).
- **Secondary NFT purchase and NAME registration: unavailable.** Evidence: [marketplace.claim-name.tsx](../packages/routes/app/routes/marketplace.claim-name.tsx), [unavailable-actions.ts](../packages/data/src/lib/catalyst/marketplace/unavailable-actions.ts).
- **Collection-item checkout: partial.** Evidence: [CheckoutWizard.tsx](../packages/features/src/components/marketplace/CheckoutWizard.tsx), [checkout-run.ts](../packages/data/src/lib/catalyst/marketplace/checkout-run.ts).

### Assumptions to validate

- **Identity:** Delegated API sign-in and on-chain wallet authority are different; ownership, chain and allowance must be checked for the action.
- **Availability:** A readable listing does not prove checkout support; relayer/payment/chain availability must be established before requesting signatures.
- **Persistence:** A typed-data signature is not a broadcast transaction; a transaction hash is not by itself a confirmed purchase.
- **Completion:** Require a receipt or authoritative checkout result for the correct asset and buyer; never synthesize a token id from a signature.
- **Measurement:** Keep reviewed listing, approval, submission and confirmed purchase distinct; unavailable flows must not emit purchase success.

## Places, editorial and utility pages

### Capabilities

- **Place and editorial browsing: implemented.** Evidence: [blog._index.tsx](../packages/routes/app/routes/blog._index.tsx), [story.md](../packages/features/src/stories/misc/browse-places/story.md).
- **Client and shop handoffs: partial.** Evidence: [story.md](../packages/features/src/stories/misc/jump-in/story.md), [story.md](../packages/features/src/stories/misc/places-shop-entry/story.md).

### Assumptions to validate

- **Identity:** Public reading needs no wallet; a handoff inherits the destination product identity requirements.
- **Availability:** Editorial content, destination data and client launch support are independent; missing data needs an explicit empty/error distinction.
- **Persistence:** Outbound navigation persists no purchase, attendance or scene state by itself.
- **Completion:** An outbound click proves a handoff only; arrival and the downstream action require their own acknowledgement.
- **Measurement:** Attribute downstream conversions only when linked by the documented session/entry context; do not equate click-through with conversion.

## Notification delivery

### Capabilities

- **First-wear delivery experiment: implemented.** Evidence: [story.md](../packages/features/src/stories/notifications/first-wear/story.md), [first_wear.rs](../../crates/catalyrst-notifications/src/first_wear.rs).
- **Delivery-to-shop attribution: partial.** Evidence: [story.md](../packages/features/src/stories/notifications/first-wear/story.md), [marketplace.ts](../packages/core/src/lib/telemetry/events/marketplace.ts).

### Assumptions to validate

- **Identity:** The recipient address is the assignment unit; browser sid is not interchangeable with that address.
- **Availability:** Worker, notification store, presence and experiment overrides must be available; a sites page cannot attest delivery.
- **Persistence:** Suppression, inserted notification, read flag and landing event represent different persisted facts.
- **Completion:** Notification insertion proves emission; only a read/landing signal proves engagement, and neither proves purchase.
- **Measurement:** Keep address-assigned worker arms separate from session experiments; preserve holdout and suppression counts in the denominator.

## Avatar and social overlay

### Capabilities

- **Community membership writes: implemented.** Evidence: [bevy-overlay.community-join.tsx](../packages/routes/app/routes/bevy-overlay.community-join.tsx), [community-commit.ts](../packages/data/src/lib/catalyst/overlay/community-commit.ts).
- **Community creation preview and avatar/voice controls: partial.** Evidence: [bevy-overlay.community-create.tsx](../packages/routes/app/routes/bevy-overlay.community-create.tsx), [bevy-overlay.backpack-equip.tsx](../packages/routes/app/routes/bevy-overlay.backpack-equip.tsx), [bevy-overlay.voice-join.tsx](../packages/routes/app/routes/bevy-overlay.voice-join.tsx).

### Assumptions to validate

- **Identity:** A rendered overlay does not guarantee a wallet, community role or renderer session; never substitute simulation when anonymous.
- **Availability:** Social API, renderer bridge and media permission are independent; microphone permission is not room admission.
- **Persistence:** Membership requires an acknowledged signed write; local avatar/voice state and preview-created communities are not shared persistence.
- **Completion:** Distinguish joined membership from a pending private-community request, and room admission from an unmuted microphone.
- **Measurement:** Measure acknowledged join/request, saved outfit and voice admission separately; preview actions must stay identifiable.
