# `catalyrst/ui3/src/generated/catalyst/` - ts-rs types mirrored from the server Rust DTOs

**Do not hand-edit anything in this directory** (except this README). Every
`.ts` file here is emitted by [ts-rs](https://docs.rs/ts-rs) from a Rust DTO in
the server workspace. They are the single source of truth that the sites
drift-guards assert each Zod schema against, so the TS type and the Rust type
serving the wire can never silently diverge.

Ground truth for *which* crate produces *what* is the
`[package.metadata.generated]` block in each emitting crate's own `Cargo.toml`;
`../INDEX.json` is the committed reverse index (artefact -> crate -> gate),
regenerated by `npm run gen:artefacts` and checked by
`npm run gen:artefacts:check`. There is no hand-maintained crate list.

Layout: one subdir per crate, named by the crate's short name (the crate name
with its shared workspace prefix dropped), nested under
`catalyrst/ui3/src/generated/catalyst/`:

```
catalyrst/ui3/src/generated/
  catalyst/
    credits/   <- the credits crate  src/dto.rs
    market/    <- the market crate   src/dto.rs
    ...        <- one dir per emitting crate
  bridge/      <- bridge_protocol (bevy<->overlay contract, bevy-explorer workspace)
  editor-bus.ts <- bridge_protocol::editor (page<->scene editor bus contract, assembled
                   single-file; mirrored byte-identical into
                   bevy-explorer/editor-scene/src/generated/ and
                   tools/scene-editor-mcp/src/generated/ by gen-ts-types.sh)
```

Both `ui3` (relative imports) and `sites` (`@ui/generated/*`) consume the same
generated files. The sibling `bridge/` dir (one level up, at
`catalyrst/ui3/src/generated/bridge/`) is generated by the same pipeline from the
`bridge_protocol` crate - see `catalyrst/sites/scripts/gen-ts-types.sh`.

## The pipeline

1. **Feature-gated ts-rs.** Each guarded DTO derives ts-rs only under the `ts`
   Cargo feature, which is **off by default** - prod builds never compile ts-rs:

   ```rust
   #[cfg_attr(feature = "ts", derive(ts_rs::TS), ts(export, export_to = "credits/"))]
   pub struct SeasonData { /* ... */ }
   ```

   `export_to` is the crate short name + `/` (e.g. `"credits/"`, `"market/"`).
   The crate's `Cargo.toml` carries:

   ```toml
   ts-rs = { workspace = true, optional = true }

   [features]
   ts = ["dep:ts-rs"]
   ```

   and declares what it emits, so the crate itself names its artefact and its
   gate - this block is what enrols the crate in the gate:

   ```toml
   [package.metadata.generated]
   gate = "catalyrst/sites/scripts/gen-ts-check.sh"
   ts-bindings = "catalyrst/ui3/src/generated/catalyst/credits"
   ```

2. **Generate** (writes into this dir). Cargo must run in the FHS shell on NixOS,
   so go through the dcl-shell wrapper:

   ```bash
   cd catalyrst/sites
   npm run gen:types          # under: linux-rigging/dcl-shell -c "..."
   ```

   `gen:types` runs `scripts/gen-ts-types.sh`, which sets
   `TS_RS_EXPORT_DIR=catalyrst/ui3/src/generated/catalyst` and runs, per ts-featured crate:
   `cargo test --features ts -p <crate> export_bindings`. (It then re-points
   `TS_RS_EXPORT_DIR` at `catalyrst/ui3/src/generated` and runs the same for the
   `bridge_protocol` crate, landing its output in `catalyrst/ui3/src/generated/bridge/`.)

3. **Guard.** Hand-written Zod schemas in `app/lib/catalyst/marketplace/*.ts`
   import the generated types and assert structural agreement (see below). Drift
   surfaces as a `tsc` error from `npm run typecheck`.

4. **CI gate.** `npm run gen:types:check` (`scripts/gen-ts-check.sh`) regenerates
   the types into a temp dir and `diff -r`s against this committed dir; it fails
   (printing the drifted files) if they differ - i.e. someone edited a guarded
   DTO but forgot `npm run gen:types`.

## The three guard styles

Pick by how the Zod schema relates to the served Rust shape. Shared helpers:

```ts
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends <T>() => T extends B ? 1 : 2 ? true : false;
type AssignableTo<Sub, Sup> = Sub extends Sup ? true : false;
type Assert<T extends true> = T;
```

| Style | Helper | When | Example |
|---|---|---|---|
| **Strict** | `Assert<Equal<zInfer, RsType>>` | The Zod schema is an exact mirror of the DTO - every field matches both ways. | `marketplace/credits.ts` |
| **Directional** | `Assert<AssignableTo<RsType, zInfer>>` | The Zod schema is nullable-tolerant / looser; assert everything the server serves is accepted by the schema. | `marketplace/escrow-lease.ts`, `orders.ts`, `bid.ts` |
| **Shared-key** | `Assert<AssignableTo<Pick<RsType, K>, Pick<zInfer, K>>>` where `K = Extract<keyof RsType, keyof zInfer>` | The Zod schema is a deliberate SUPERSET (requires fields the server does not serve); guard only the keys both have. | `marketplace/schema.ts` (`_DriftItem`) |

## ts-rs gotchas (v10)

- **`i64`/`u64` -> `bigint`, but they ride the wire as JSON numbers.** Annotate
  the field `#[cfg_attr(feature = "ts", ts(type = "number"))]`.
- **Combined `#[serde(rename = "x", skip_serializing_if = ...)]` makes ts-rs DROP
  the rename.** Prefer a struct-level `#[cfg_attr(feature = "ts", ts(rename_all = "camelCase"))]`
  to match the serde wire shape, or split the serde attrs apart.
- **A `#[serde(into = "u64")]` enum (e.g. `ChainId`)** should `ts(type = "number")`
  on that FIELD - do not derive a TS enum.
- **A loosely-modeled field (Zod treats it as a `Record`)** should be
  `ts(type = "Record<string, unknown>")` to avoid a deep type cascade.

## Workflow rule

After changing a **guarded** Rust DTO, run `npm run gen:types` and commit the
regenerated `.ts`. CI runs `npm run gen:types:check` (drift gate) followed by
`npm run typecheck` (guard check).
